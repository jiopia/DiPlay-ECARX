# 实现方式、进度与未解难题

这份文档回答三个问题：**它是怎么接进去的**、**现在做到哪一步**、**卡在哪里**。
偏工程视角，写给要接手、要改代码、或要在别的车上复现的人看。

用户向的安装与使用说明在 [`README.md`](README.md)，两者不重复：README 讲「怎么用」，
本文讲「为什么能跑」和「哪些地方还没跑通」。

> 更新于 2026-11-09。这里的所有结论都来自**一台车**（领克 05 2020，亿咖通 DCY11）的实车调试，
> 标注为「未验证」的条目就是字面意思——没有在车上确认过，不保证。

## 一、实现方式

### 1.1 三层结构

```
┌─────────────────────────────────────────────────────────────┐
│  AirPlay / iAP2 协议层      shared/.../airplay              │
│  连接协商、/info 能力声明、视频流解码、音频、遥控通道        │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│  车机集成层（本移植版新增） common/.../                     │
│  CarPlayHostActivity、显示窗口、DIM 桥、媒体桥、设置页       │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│  平台通道          ECARX 私有 API（signature 级）与标准 API  │
│  DIM · MediaCenter · MediaSession · 车机投屏开关             │
└─────────────────────────────────────────────────────────────┘
```

协议层沿用上游，重写的是**中间那层的整个下半截**：上游把仪表交给比亚迪的 HUD / DiLink 集群节点，
本移植版把那一整段删掉，换成亿咖通的 DIM。

关键点：**仪表不是靠「投屏」做的**。上游客厅里那个「仪表投屏」开关，本质是把中控画面镜像到
仪表（display 1），一旦打开，仪表上就会出现两套画互相盖。本移植版走的是另一条路——在 display 1
上自建一个窗口，把 iPhone 直发的**原生集群视频流**装进去。

### 1.2 连接与控制通路

支持的入网方式（都在设置页「连接设置」里选）：

| 方式 | 说明 |
|---|---|
| USB 有线 | 协议层支持，**本车未验证**（见 §3.8） |
| Wi-Fi Direct | 车机与 iPhone 直连，不依赖外部 AP |
| 车机热点 | 由 App 拉起热点，iPhone 加入 |
| 已有 Wi-Fi | 两边都在同一个 AP 上 |

无线通路上真正难的不是传输，是**选对手机**和**让位给蓝牙**：

- iPhone 同时被两条链路牵着——CarPlay（AirPlay）和车机经典蓝牙（A2DP/HFP）。经典蓝牙只要还连着，
  iOS 就倾向把音频交给蓝牙，车机音源也停在蓝牙音乐上。**必须切断经典蓝牙**，音频才会走 CarPlay。
  代价是车机拿不到 AVRCP 元数据，仪表媒体卡片只能由 App 自己推。这是一组配套取舍。
- 切断时机极敏感：CarPlay 会话建立（iAP2 认证 → AirPlay 启动）约需 1 秒多。**1 秒就关蓝牙会打断
  握手，表现为有画面无声音；2 秒正常。** 这条已写进 README 的快捷指令步骤里。

### 1.3 两块屏幕

车机对外暴露两块 display：

| display | 归属 | 分辨率 | 本项目怎么用 |
|---|---|---|---|
| 0 | 中控 | 1920×1080 | `TextureView` 装主视频流（协议里 `coded=1920x1088`，含 8 行对齐填充） |
| 1 | 「HDMI 屏幕」，物理接仪表 | 1920×720（8:3） | 自建 `Presentation`，装集群视频流（设备内标识 **111**） |

display 1 有一个不寻常的属性：`flags=0xb`，且 `activeStreams` 里平时**不含** 111——
也就是说车机固件自己并不把 111 当集群流用，这个映射是 App 打开 `loadClusterMapEnabled`
之后才建立的。

**「把 display 1 接到仪表」是一个独立开关**，即 `setPresentationToDimSwitch(boolean)`。
它不是镜像开关，而是通路开关：

- `false` —— 摘掉通路，车机立刻盖回它自己的仪表页；
- `true` —— 才真正把 display 1 送到仪表。

所以顺序固定：**先 `show()` 窗口，再 `true`**；收尾反过来，**先 `false` 再 `dismiss()`**。顺序颠倒
会留残影或闪一下。这个状态存在车机侧、跨进程存活，进程被杀后仍然保持「已接通」——所以启动时必须
主动释放一次，否则仪表会变成中控镜像。

### 1.4 仪表的三条并行通路

仪表上的信息不是一条链路，是三条，互不影响，也各自会单独坏：

| 通路 | 承载内容 | 通道 | 判活标志 |
|---|---|---|---|
| **视频** | 整幅车道级地图 | 集群视频流 → display 1 的 Presentation | 该窗口有帧、`coded=1920x720` |
| **导航数据** | 转向箭头 id、距离、路名、ETA | ECARX **DIM** `INaviInteraction` | `DIM arrow=… arrowId=NNN` |
| **媒体卡片** | 曲名/歌手/专辑/状态/封面 | ECARX **DIM** `IMediaInteraction` | `media counters … cover=` |

导航那条还有一个易错点：**导航开始时不发投屏调用**。车机自己在导航开始时会去抢仪表屏，
此时 App 只需要把通路交还给平台，等它抢完再取回——提前抢会导致「仪表闪一下」或者干脆不出图。

媒体卡片只接受**图片 URL**，不接受字节流。协议里 `IPlaybackInfo` 和 `IMedia` 是两套（20 与 14），
封面只能走前者，所以 App 在本机回环地址上起一个极小的 HTTP 服务，把封面按 JPEG 供出去
（`http://127.0.0.1:<随机端口>/cover/<n>.jpg`）。车机侧加载器是 `uid.system`、明文 HTTP，这条能通。

### 1.5 音频

- 播放：iPhone 下发的 PCM 直接喂 `AudioRenderer`。
- **导航播报压低音乐（duck）**：iPhone 给的 `volume` 是一个**负数 dB**，含义是「接收端需要压低多少」，
  不是音量本身。正确做法是把 dB 转成线性增益，按 **0.75 dB / 块**的斜率做斜坡，避免爆音。
  （车机自己的 `setStereoVolume` 在本平台被忽略，只能自己算。）
- 这个开关与「导航提示音音频焦点」**无关**，是两个独立机制，排查时不要混。

### 1.6 方向盘按键

车机上按键有三条可能的路，本项目都探过：

| 路 | 状态 | 说明 |
|---|---|---|
| `MediaSession` 传输指令 | ✅ 可用 | 媒体键最稳的一条，走标准 API |
| `Dcy11InputManager`（车机私有） | 🚧 未接线 | 服务确实存在，键码含义未定（见 §3.5） |
| 无障碍服务 | ⚠️ 部分 | 只能拿 Siri / 缩放类手势，媒体键 `presses=0` |

「语音键被响应两次」是 ROM 行为：车机自带助手和本 App 同时收到这一下按键，且 ROM 不把按键独占
交给第三方。目前只能停用车机助手。

### 1.7 CarPlay Ultra（主题仪表）

Ultra 是 iOS 侧给「仪表有主题 UI」这类车准备的一套机制，比普通 CarPlay 多三层东西：

1. **displayPanels**：在 `/info` 里告诉 iPhone「这块屏上要摆哪些面板」，
   每个 panel 带 `displayPlugins` / `showsInstruments` / `initialVideoStreams`。
2. **主题资产**：iAP2 里声明一个 `assetIdentifier`，iPhone 据此挑一套主题描述（含分区、圆角、内缩）。
3. **uiSync 通道**：iPhone 下发插件的布局与状态，App 回报触摸与滚动。

**半开状态会黑屏**：只开 Ultra 不开主题时，如果仍然发 `displayPanels`，iPhone 会拿到「要被插件填满、
却没有视频流」的屏，中控整块黑。正确约束是——**只在主题模式打开时发 panels**，且两块 display
都换成主题对应的名字。这条是本项目踩出来的，不是文档里写的。

### 1.8 构建与签名

- 车机是 `test-keys`，所以用 **AOSP 平台密钥**签名就能拿到 signature 级权限，去调 DIM 这类私有 API。
  这是整个方案能成立的前提：普通第三方签名拿不到 `DimInteraction`。
- 发布包**默认不含** Apple 的配件身份（`offline-mfi/`），要在车上连 iPhone 必须自己构建一版。
- 构建产物与校验命令见 [`BUILD.md`](BUILD.md)。

## 三、未解难题

按阻塞程度排序。「已排除」的意思是**试过并且知道自己错在哪**，重走一遍没有意义。

### 3.1 Ultra 主题模式中控只填顶部 66%

**现象**：主题模式下，中控画面正常渲染，但内容只占顶部 720 行（1080 的 66%），下面 360 行全黑。
像素探针读数固定为 `box=0,0..100,66`，`drawn≈11%`。

**已排除**：

- 不是窗口尺寸问题——把 viewArea 改成 1920×880 后比例仍是 66%；
- 不是 safeArea / 遮罩问题——主题模式下这两项已被显式忽略，全幅下发；
- 不是流的问题——110 流 `coded=1920x1088`（全高），111 流 `coded=1920x720`；
- 不是码率问题——110 流静止时 `0.8fps / 1kbps` 是保活帧，不代表黑屏。

**当前判断**：Ultra 主题场景的**规范画布就是 8:3**。四条独立来源都指向这个比例（本机实测 720/1080、
111 流 1920×720、同平台另一分支固定 1920×720、车厂参考实现 2.69 与 1.67）。真实 Ultra 车是贯穿式
宽屏，主题场景按宽幅设计，iPhone 把一块 8:3 的内容**顶部对齐**放进 16:9 画布，剩下的自然留黑。

**这意味着**：改 safeArea、viewArea、窗口参数都无效，这是内容几何而不是可用区。

**下一步（三条路，按成本）**：
1. 把中控在主题模式下声明成 1920×720，看 iPhone 是铺满还是等比缩放到宽度（零代码，A/B 即可）；
2. 接受 66%，把下方 360 行由车机自绘（信息条/媒体/车控），即「宽幅画布 + 自绘补充」；
3. 放弃 Apple 主题仪表，改自绘宽幅合成——本车缺仪表端 native 注入，只能喂中控。

### 3.2 主题参数是「全有或全无」

**现象**：给 iAP2 的 theme 参数增加一个字段，整包会被 iPhone 拒（报 `Unknown body parameter`），
不是忽略，是整个请求失败。

**已定位**：参数是**强 schema**，必须在协议层的 endpoint 描述里同步登记 children，少一个就报未知。

**影响**：任何 Ultra 参数实验都必须同时改两处，否则一次实验要浪费一整轮上车。

### 3.3 主题模式四角变圆角

**现象**：主题会话开始后，中控四角出现圆角。会话是**全幅 safeArea、且没有下发 `cornerMasks`**。

**当前判断**：`cornerMasks` 字段**缺席**时，iPhone 会按主题资产里的默认值自己画圆角
（参考实现里默认是 13 像素角）。同平台另一个开源实现是每个 display 都**显式下发 `false`**。

**下一步**：显式下发 `cornerMasks=false`，单独一版验收（不要和 §3.1 的画布实验混在一版里，
否则圆角会干扰对画面边界的目视判断）。

### 3.4 仪表要不到车辆数据

**现象**：Ultra 主题的仪表位置可以放车速、转速、胎压，但这台车取不到值。

**已定位**：全车数据走 VHAL（`CarPropertyManager`），APK 侧不做 CAN 解析。可枚举的 sensor 属性表
共 43 项，**只有续航里程与总里程有值**，转速/挡位/胎压恒空。

**含义**：不是权限问题，是车机没有把这些信号放进 VHAL。除非车机固件侧另有通道（DIM 或其他私有
服务），否则这条路封死，主题仪表上这些格子只能留空或自绘假值（不建议）。

### 3.5 方向盘按键的键码未知

**现象**：媒体键与方控在 CarPlay 屏上有的认、有的不认。

**已定位**：车机有 `Dcy11InputManager` 私有服务（「服务不存在」这个假设已排除），但**键码含义未知**。
当前实现同时认两套码（车机私有 200xxx 与 AOSP 87/88/85），未认领的键会记进日志。

**下一步**：在车上逐键按一遍，看日志里出现哪一套码，再决定收哪一路。

### 3.6 原厂导航服务不可调用

**现象**：想把导航状态直接告诉车机原厂导航服务，失败。

**已定位**：该服务锁在一个 **OEM 自有签名的权限**（`OPENAPI_NAVI_PERMISSION`，0x12）上，不是 AOSP
平台钥能解的——本项目的平台签名在这堵墙前无效。

**含义**：封死。导航数据只能走 DIM（已实现），不能冒充原厂导航。

### 3.7 无线连接选错手机

**现象**：车里有两台已配对 iPhone 时，连错；或者记住的那台不在车里时干脆不连。

**已定位**：早期实现只按「蓝牙名包含 iPhone」判断，改名就认不出；fallback 只接受「已连接」的另一台，
因此目标手机不在场时会卡在 RFCOMM 5.1 秒超时后放弃。

**当前实现**：名字、iAP2 UUID、设备类型三重判定；fallback 遍历**已配对**设备而不是已连接设备；
连上后回写地址，下次直接连。已实车验证。

### 3.8 有线 USB 完全未验证

协议层支持，但在这台车上没试过。线材、USB 角色、iAP2 握手都可能暴露无线路径上不存在的问题。
**不要从「无线好用」外推「有线也好用」。**

### 3.9 无法自举无线 ADB

**背景**：调试时需要不插线进 shell，但 Android 9 没有系统级「无线调试」。

**已定位**：无线 ADB 的唯一实质是 adbd 监听 TCP:5555，只能由 `service.adb.tcp.port` /
`persist.adb.tcp.port` 两个 system property 产生。本机**没有 `su`**（只有 adbd 自己可以 root），
普通 App 写这两个属性被 SELinux 拒。

**含义**：装任何「WiFi ADB / ADB 助手」类 App（包括 SSH 服务端）都无法开端口——它们要么是客户端，
要么需要 root。可行的只有：插一次线执行 `adb tcpip 5555`（重启失效），或 `adb root` 后写
`persist.adb.tcp.port`（永久）。

### 3.10 只验证过一台车

所有结论都来自一台 2020 款领克 05（`IP732` / 固件 `AP_DCY11_…_20012107`）。display 编号、仪表尺寸、
DIM 版本、是否有 `Dcy11InputManager`，在别的亿咖通车型上都可能不同。移植前先跑一遍设备探测。

## 四、工程约束（踩过的坑）

这些不是观点，是**违反就会静默失败**的规则。新接手的人最值得先读这段。

| 约束 | 后果 |
|---|---|
| `android:windowBackground` 必须是资源引用 | 字面色值在 ≤ Android 9 上等于窗口透明，对话框会压在背后页 |
| 车机侧投屏开关状态跨进程存活 | 进程被杀后仍保持「已接通」，启动时不释放就会盖掉仪表 |
| `setPresentationToDimSwitch` 顺序 | 先 show 后 true、先 false 后 dismiss，颠倒会闪或留残影 |
| 主题参数与 `/info` schema 强绑定 | 加参数不同步登记 children 会整包被拒 |
| Ultra 开关必须成对 | `ultra=on / theme=off` 仍发 panels ⇒ 中控整块黑 |
| 删私有分支前先分清哪段通用 | 车机专属的「热点自动开」入口寄生在别家分支的 else 里，一起删会静默失效 |
| 判「画面黑不黑」别看码率 | 静止时 1 kbps 是保活帧 |
| 判「视频流在不在」看实际帧 | 没有帧探针时，`LISTEN` 与「已就绪」是两件事 |

## 五、怎么验证（不要凭现象猜）

1. **先抓诊断报告**：设置 → 诊断 → 保存诊断报告。仪表与媒体的关键判读行在 README 里列了。
2. **像素探针**：调试版每 5 秒取一次画面缩略图，输出 `frame probe … drawn=…% box=x0,y0..x1,y1`。
   `box` 是内容包围盒的百分比坐标——**判断「没铺满」靠它，不靠肉眼**。
3. **亮度图**：每 30 秒输出一张 32×18 的字符亮度图，用来看「黑在哪一块」。
   （字符集刻意避开十六进制字母，避免被日志脱敏规则整行吃掉。）
4. **构建三件套**：签名校验（平台钥指纹）＋ 类集合比对（新增 lambda 会位移编号，报 `removed=1 added=1`
   属正常）＋ 功能契约脚本。三者任一不过，包不上车。
